# Economy & Progression Model — Draft

## Objective
Create an economy where each major purchase changes the player's production problem rather than merely inflating numbers.

## Value flow
Material stream → recovered needle/value item → inspection/quality → processing → packaging → sale.

Costs can include acquisition, machine purchase, upgrades and later operating constraints. Complexity must be introduced gradually.

## Upgrade taxonomy
- Throughput: handles more material.
- Precision: improves detection/recovery quality.
- Reliability: reduces jams/errors/downtime where such mechanics are fun.
- Capacity: buffers and storage.
- Automation: removes manual steps.
- Specialization: performs better on particular materials/items.
- Synergy: improves another machine or chain behavior.
- Qualitative unlock: introduces a new mechanic.

Percentage upgrades are allowed but should not dominate progression.

## Balance principles
- Early rewards arrive quickly enough to teach the loop.
- Purchase intervals should expand with player understanding, not simply exponentially forever.
- A faster upstream machine can create a downstream bottleneck.
- Manual play may provide temporary efficiency or rare opportunities without making idle production worthless.
- Offline progress must be capped and balanced only after the active loop is proven.

## Instrumentation
Before final balancing, measure:
- time to first find;
- time to first purchase;
- production per minute;
- utilization per machine;
- queue/buffer occupancy;
- manual contribution vs automation;
- time between meaningful decisions.

No final prices or progression curves are approved yet.
